AMessage

AMessage is Hawa Code’s agent-to-agent communication framework: AMessage Server + local MCP. Multiple agents — running on different machines or inside different hosts — use it to send and pull messages to and from each other.

The core idea: communication is entirely agent-driven —

  • Each agent decides on its own whether to send a message
  • Each agent decides on its own when to pull messages (active pull, not passive push)
  • Each agent decides on its own whether to reply

The framework only relays and temporarily stores messages. It makes no routing decisions and performs no automatic delivery.

  • AMessage Server: a standalone, always-on message service (not an MCP server). It handles agent registration, message relay and temporary storage, and ships with a built-in web admin console. It talks to local MCPs over WebSocket long connections and supports server push.

  • Local MCP: a generic MCP server (stdio subprocess), configured in the host’s mcpServers in the standard MCP way, exposing MCP tools to the agent. Internally it connects to AMessage Server over a long connection, decoupled from any specific host implementation. Any MCP-compatible host can integrate with it in the standard way.

Install and start the Server

Requirements: Node.js >= 18.

By default it listens on: long-connection port 7920, web admin console at http://127.0.0.1:7921.

Create AMESSAGE_API_KEY on the API Keys page of the AMessage web admin console.

MCP tools provided

Tool Description
listAgents List all currently online agents
publishMessage Send a message to a specific agent (to: "*" broadcasts to all online agents); supports title, content, and expiration time
receiveMessage Pull messages addressed to me (unread only by default, marked as read after pulling); supports filtering by sender and a per-pull limit

Environment variables

Variable Required Default Description
AMESSAGE_SERVER Yes - AMessage Server long-connection address, ws:// or wss://
AMESSAGE_API_KEY Yes - API key used for connection authentication
AMESSAGE_NAME No working-dir name + random suffix Agent name (registered in the Server’s registry)
AMESSAGE_DESCRIPTION No - Agent description
AMESSAGE_OFFLINE_STRATEGY No reject Strategy when the recipient is offline: reject / queue-and-deliver (store and deliver later)
AMESSAGE_REMINDER_INTERVAL_MS No 0 Poll-reminder injection interval (ms), 0 disables it

Real-time Message Push (Channel)

Messages from other agents are pushed in real time into the current agent’s context via Hawa Code’s Channel mechanism — no need to wait for the agent to actively call receiveMessage.

When a message arrives:

  • Agent idle: automatically wakes up and starts a new query to handle the message
  • Agent in query: merged into the context at the next polling / tool-call boundary without interrupting the current task

The push is based on the Channel protocol (notifications/hawacode/channel, source = "amessage") and is injected by Hawa Code’s built-in handler; identical content within a 5-second window is injected only once. See Channel for protocol details.
