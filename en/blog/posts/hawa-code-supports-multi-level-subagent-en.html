Hawa Code 支持多层级 Subagent

2026-07-31 hawa code

Hawa Code 早期 Subagent 只能同步执行，同时 Subagent 只支持 1 层级，也就是 Subagent 不能再创建 Subagent。后期 Hawa Code 支持 Agent Team 功能，Agent team 成员可以创建 Subagent，但是普通的 Subagent 还是不能再创建 Subagent Agent。当前 Hawa Code 已经开放多层级使用，用户可以自定义设置 Subagent 1～5 层级。

上下文窗口占用

Subagent 初期是解决上下文窗口占用的问题。如果分析一个大任务，可能任务还没有结束就需要进行上下文压缩。主 Agent 可以通过 Subagent 拆分多个任务来执行，主 Agent 中只需要获取 Subagent 的返回结果，这样主 Agent 上下文窗口占用就非常少。

Subagent 被分配到任务是否一定是小的？比如修改小 bug 看似是一个小任务，但是遇到非常隐秘的 bug 可能需要搜索大量的代码文件，同样会占用大量的上下文窗口；或者中间遇到大段的文本内容，同样需要占用大量的上下文窗口。多层 Subagent 在很多场景中是必须的。

Token 节省

Subagent 是否可以节省 Token？这个问题答案不是确定的。一个子任务被 Subagent 执行完成，这个任务执行过程无需在主 Agent 上下文中重复传输，从这个角度讲 Subagent 是可以节省 Token 的。

如果一个 Agent 分析多个任务，分配给 Subagent 的时候一般只有任务要求和描述，历史任务分析过程是会丢失的。如果两个有关联的任务都在主 Agent 中执行，这两个任务相关的内容就不需要重复分析；拆分到两个 Subagent 的时候可能会出现重复分析情况，从这个角度讲会消耗更多的 Token。

一般情况下，相对复杂的长时任务，Subagent 会降低 Token 消耗。

Subagent 层级建议

如果都是简单任务，Subagent 层级 1 就可以胜任。如果是长时任务，同时会有大量文本和代码分析，Subagent 可以开启多层级，一般默认 3 级就可以。最高不需要超过 5 级，更多层级的 Subagent 不一定会带来更好的任务执行效果。
