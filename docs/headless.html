Headless

Headless

Headless 模式让 Hawa Code 在不启动终端交互界面的情况下运行，适合无 UI 环境、远程服务和自动化场景。需要说明的是，Headless 并不是通过 --headless 参数开启的，Hawa Code 提供以下两种无终端 UI 的用法：

  1. hcode server：Headless 常驻服务。进程常驻、不渲染终端 UI，内置 WebServer（HTTP + WebSocket），通过浏览器远程控制。这是官方的 Headless 运行模式。
  2. hcode -p "..."：单轮非交互模式。执行一次任务、将结果打印到标准输出后退出，适合管道和脚本调用，但不是常驻服务。

注意：配置项 headlessBrowser（无头浏览器）用于网页抓取渲染，与 Headless 运行模式无关，不要混淆。

1. 两种模式的区别

对比项 hcode server hcode -p "..."
运行方式 进程常驻，不退出 执行单轮后退出
交互能力 浏览器实时交互、审批工具调用 无交互，一次性输出
适用场景 远程常驻服务、无 UI 环境 CI/CD、脚本、管道调用
  • 需要”在远程机器上长期运行、通过浏览器使用完整 Agent 能力”时，使用 hcode server。
  • 需要”在流水线里跑一条命令、按退出码判断结果”时，使用 hcode -p。

2. 使用 hcode server 启动 Headless 服务

2.1 命令格式

此外还提供一个独立的 dist 入口，可直接用 node 启动构建产物，参数与 hcode server 相同：

2.2 参数说明

参数 说明
--resume <id> 恢复历史会话（匹配日志完整路径或文件名后缀 <id>.jsonl），找不到时以退出码 1 退出
--cwd <path> 指定工作目录，默认为进程启动时的当前目录
--verbose 输出详细信息
--dangerously-skip-permissions 跳过所有权限确认，存在安全风险，详见注意事项

WebServer 完全由 settings 配置驱动（settings.webServer.enabled 等），不再提供 --port / --host / --token 等命令行覆盖参数；端口与绑定地址请在 settings 中配置，默认绑定地址为 0.0.0.0。使用 hcode server 前请确保已在 settings 中开启 webServer.enabled；若未开启，进程仍会启动但仅打印 Hawa Code headless server started (WebServer disabled, set settings.webServer.enabled=true to enable) 提示，不会拉起 WebServer。

2.3 登录鉴权

Web 端已改为用户名 + 密码登录鉴权（不再使用 --token 参数），并内置登录页：

  • 默认凭据：未配置时为 admin / admin，不落盘存储；首次登录后请尽快修改。
  • 凭据存储：以 scrypt 哈希保存在用户级 settings（~/.hcode/settings.json 的 webServer.username / passwordHash / authSalt）。
  • 修改入口：终端 /config 的 Web Server username/password 项，或 Web 端”设置 → Account”（需当前密码验证）。
  • 会话 token：登录成功后由服务端签发 HMAC 签名 token，有效期 7 天；HTTP 请求通过 Authorization: Bearer <token> 传递，WebSocket 握手通过子协议或 ?token= 传递。修改密码后旧 token 立即失效，需重新登录。
  • 接口：GET /api/auth/status（登录状态）、POST /api/auth/login（登录获取 token）、POST /api/auth/change-password（修改凭据）；其余 /api/* 与 /ws 无有效 token 时返回 401。
  • 使用默认凭据登录时，Web 端会显示修改密码的警告横幅；绑定非回环地址且使用默认凭据时，启动输出弱口令告警。

2.5 后台运行

在 Linux/macOS 服务器上常驻后台运行（日志写入文件，标准输入重定向避免阻塞）：

  • 标准输入必须重定向为 /dev/null（或设置 CI=true），否则管道场景会因等待 EOF 而阻塞启动。
  • 启动输出与错误写入 hcode-server.log，会话日志仍位于 UCODE_ROOT_DIR/projects/<项目目录>/。
  • 停止服务：pkill -f "cli.js server"（按进程实际命令行匹配；hcode shim 被 exec 后命令行中不含 “hcode” 字样，按 "hcode server" 匹配不到），或直接 kill <PID>。
  • 生产环境更推荐使用 systemd 或 Docker 托管，详见第 6 节。

3. 前置条件

  1. 先完成终端模式初始化：Headless 模式跳过 Onboarding、信任对话框、MCP 审批等依赖终端交互的步骤，因此请先在终端模式中运行一次 hcode，完成模型/API 等初始化配置。
  2. 模型与 API 配置：请确保模型和 API 已通过终端模式配置完成且有效，配置无效时启动或查询会报错。
  3. 登录凭据：Web 端通过用户名+密码登录。绑定非回环地址对外提供服务前，请先通过终端 /config 或 Web 端设置修改默认凭据（admin/admin），避免弱口令暴露。
  4. 工作目录：进程会自动授予 --cwd 目录的读取权限，无需终端信任确认。

4. 启动后如何判断成功

启动成功的标志：

  1. 标准输出依次出现 Hawa Code headless server starting...、Tools, commands and MCP clients loaded, starting Web server...。
  2. 随后出现 Hawa Code headless server started 与访问 URL（例如 URL: http://0.0.0.0:3210）及启动耗时。实际端口以启动输出中的 URL: 为准（端口冲突时已自动 +1）。
  3. 进程保持常驻不退出，用浏览器打开该 URL，登录后即可使用。

启动会话后，终端标准输出不再打印会话内容；会话消息以 JSONL 形式落盘，并通过 WebSocket 实时推送到浏览器。进程支持 SIGINT/SIGTERM 优雅关闭（kill <PID> 即可正常退出）。

5. 日志与排查

日志位于 UCODE_ROOT_DIR/projects/<项目目录>/ 下：

路径 内容
messages/*.jsonl 会话消息记录
log/*.log 运行日志
log/error-<日期>.log 错误日志
errors/*.txt 错误记录
mcp-logs-<server>/ 各 MCP Server 的日志

常见失败信号与退出码：

现象 说明
Failed to start WebServer: ... 并以退出码 1 退出 WebServer 启动失败，常见于端口占用、settings 中未开启 webServer.enabled 等
WebServer 30 秒内未就绪 serverRunner 等待 WebServer 就绪超时，请检查 settings 的 webServer 配置与端口占用情况
Session log not found: <id> 并以退出码 1 退出 --resume 指定的会话日志不存在
启动成功后进程被杀或退出 属于异常，请查看错误日志

排查顺序建议：先看标准输出中的提示 → 查看 log/error-*.log → 检查浏览器端是否已登录（未登录访问 /api/* 与 /ws 会返回 401）→ 必要时查看 MCP 日志。

6. CI/CD 与脚本场景

  • 优先使用 hcode -p：执行一次查询、将结果打印到标准输出后以退出码 0 退出，适合作为 CI 步骤按退出码判断结果。

    标准输入无内容时进程以退出码 1 退出。

  • 常驻远程服务/无 UI 环境使用 hcode server：在服务器、Docker、systemd 中常驻运行，浏览器作为前端。

  • 批量与自动化任务：可先调用 POST /api/auth/login 获取会话 token，再通过 WebServer 的 REST / WebSocket API 程序化提交任务（请求需携带 Authorization: Bearer <token>）。

7. 注意事项

  1. 权限确认需要有人在浏览器侧审批：Headless 模式下唯一的审批通道是 Web 客户端；没有任何客户端响应时，工具确认约 5 分钟后超时。
  2. --dangerously-skip-permissions 的安全风险：该参数会跳过所有权限确认，Headless 路径未执行终端模式中的隔离环境校验，请务必仅在受信任的隔离环境中使用。
  3. 后台运行时注意标准输入：通过 systemd、docker run -d、nohup 等方式后台运行不受影响；但管道/ heredoc 场景（如 somecmd | hcode server）会因等待标准输入 EOF 而阻塞启动，后台运行请确保标准输入为 /dev/null 或设置 CI=true。
  4. 端口冲突自动处理：端口被占用时自动 +1 重试，实际端口以启动输出 URL: 行为准。
  5. 登录凭据安全：凭据以 scrypt 哈希存储在用户级 settings 中，但默认凭据（admin/admin）为公开已知值，仅适合本机体验；任何对外暴露前务必修改，改密后旧会话 token 立即失效。
  6. 其他限制：无内建任务超时与失败重试；--resume 跨会话恢复的完整性未经充分验证；Headless 路径不执行 SessionStart hooks，依赖该 hook 注入上下文的用户请注意。
