Webhook

Webhook 是 Hawa Code 的通用外部事件接入通道：任何能发 HTTP 请求的系统（CI、监控、Git 平台、定时任务、自建业务服务）都可以把事件实时推进 Agent 的对话上下文，Agent 无需轮询。

它由内置 MCP Server @dahawa/hawa-channel 提供，基于 Channel 协议 注入通知。

能做什么

典型场景：

  • CI 构建失败/成功告警
  • 监控异常推送
  • Git 平台 PR、Issue 事件
  • 任何自定义系统的异步通知

::: warning
WEBHOOK_ENABLED=true（默认即为 true）时 WEBHOOK_SECRET 必填，否则启动报错。
:::

环境变量

环境变量 默认值 说明
WEBHOOK_ENABLED true 是否启用 Webhook HTTP 接收服务
WEBHOOK_HOST 127.0.0.1 监听地址；对外提供服务时改为服务器 IP 或 0.0.0.0
WEBHOOK_PORT 9527 监听端口
WEBHOOK_SECRET 无 HMAC 验签密钥，仅用于验签，不要写入日志
WEBHOOK_ALLOWED_IPS 空 逗号分隔的客户端 IP 白名单；空表示不限制
LOG_LEVEL info debug / info / warn / error

Webhook 与钉钉能力相互独立，可单独开关。

发送请求

接口

channel 只能包含小写字母、数字、下划线和中划线（^[a-z0-9_-]{1,32}$），用于区分事件来源，例如 ci、monitor、git。

请求头

头 必填 说明
Content-Type 是 必须为 application/json
X-Timestamp 是 Unix 秒级时间戳
X-Signature 是 sha256= + 64 位十六进制 HMAC

签名算法

签名针对原始请求体计算，JSON 格式化差异（空格、字段顺序）都会导致验签失败，请先签名再原样发送。

时间戳与当前时间偏差超过 5 分钟会被拒绝；相同 channel + 时间戳 + 请求体 的重复请求会被重放保护拦截。

请求体

任意 JSON 对象。通知正文按以下优先级提取字段：text → message → content；都不存在时退化为紧凑 JSON 字符串。event 字段会作为元数据传给 Agent。

响应码与排错

HTTP 状态 含义
400 channel、Content-Type、请求体 JSON 或 Content-Length 非法
401 缺少/错误的时间戳或签名、时间戳超出 5 分钟窗口、重放请求
403 客户端 IP 不在白名单
404 路径或请求方法不匹配
413 请求体超过 1 MiB
429 同一 channel 超过每分钟 60 次限流
500 服务内部错误

排查建议：

  • 启动报错缺少 WEBHOOK_SECRET：配置环境变量后重启 hawa-code。
  • 一直 401：核对密钥是否一致、时间戳是否为秒、签名是否基于原始请求体。
  • 提示 403：检查 WEBHOOK_ALLOWED_IPS 是否包含客户端地址。
  • 收不到通知：hawa-channel 的日志走 stderr（MCP stdout 只承载协议），提高 LOG_LEVEL=debug 查看。

原理简述

  • 验签：HMAC-SHA256(密钥, 时间戳 + "." + 原始请求体)，密钥双方共享，请求方证明、接收方校验，密钥本身不出现在网络传输中。
  • 时效与重放：时间戳 5 分钟有效窗口 + 内存重放缓存，拦截过期请求和原样重放。
  • 保护机制：按 channel 令牌桶限流（60 次/分钟）、请求体 1 MiB 上限、可选 IP 白名单。
  • ACK 后异步处理：先返回 HTTP 200，再规范化消息并通过 MCP notification（notifications/hawacode/channel）推给 hawa-code，外部系统不会因 Agent 处理慢而被阻塞。
