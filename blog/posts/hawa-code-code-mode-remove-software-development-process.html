Hawa Code Code Mode 如何去掉软件的开发环节？

2026-10-11 hawa code

AI Coding 发展非常迅速，颠覆了很多开发理念，但是软件依然是需要开发出来然后才可以使用，vibe coding 可以让不懂 IT 技术的人开发软件，但是依然需要先去开发一款软件，然后来使用它。

Hawa Code 理念是用户不需要去特意开发一款软件，只需要和 Hawa Code 对话解决自己的问题，Hawa Code 会渐进式生成一款软件来解决用户问题，从而模型推理环节会被逐渐被取代掉。

简单示例

我们通过一个简单的例子来看看它的基础原理

首次执行

给 Hawa code 下发一下的指令：

查询我 github 账号上所有 Java 项目提交总次数，不包括 fork 项目，提交人只统计我自己，不统计其他人

Hawa Code Code Mode 主要执行逻辑如下：

  • 查询需要的 API
  • 获取 API 详细信息
  • 进行业务查询，返回结果
  • 同时保存这个通用场景的业务代码

再次执行

如果 Hawa Code 收到类似场景的指令，其会执行如下逻辑：

  • 查询 API
  • 搜索到了可以解决当前指令问题的代码，执行这个代码并返回执行结果，不再进行推理。

基础原理

Hawa Code 在处理用户问题过程中，会把用户的问题抽象为通用场景，生成代码并保存下来，再遇到类似问题直接执行代码而不再依靠推理来解决问题。 code mode 底层是一些基础 API、可以人为扩展，这些 API 就像移动 APP 开发的 SDK ，生成的代码就是在 SDK 封装了一层新的 API，这些代码 API 依然可以被其它代码调用。最终可以支撑复杂的应用。

上述示例只是一个简单示例，后续我会单独写一个查询火车票文章，用户只需要通过 Hawa Code 使用各种方式查询火车票，比如下周六从北京去杭州，中间要经过溧阳站，时间最短的车次。在用户多次查询过程中 Hawa Code 慢慢就生成了一个火车票查询应用。

推理成本 VS 确定性

当前模型推理成本还是非常高的，而执行代码就会廉价很多，同时推理速度是非常慢的，而执行代码速度快很多，推理和代码混合执行，可以使 Agent 付出极少的的成本就可以支持复杂并且流量大的业务。

模型推理是“概率”，在很多场景下对于不确定性容忍性是非常低的，比如交易、转账、支付，不可能存在任何误差， 代码化可以把不确定变的确定。

定制化

传统 IT 软件更多的是通用，可复制，但是在 AI 时代， Agent 助手是定制化，每个人都会有一个匹配自己性格、工作行为的智能助手，但是“定制”这个环节是不需要的，Agent 助手会根据用户的行为成长为需要的样子。

Hawa Code 要做到什么？

质量可靠

自动沉淀的代码必须是可靠的，Hawa Code 不会直接保存新生成的代码，而是只会保存已经解决了真实用户问题代码。这些代码再保存前已经是经过测试验证，同时当业务发生变化，Hawa Code 同样会去订正这些代码。

丰富的 BaaS 服务

当前 Hawa Code ode mode 支持 MCP 服务扩展，通过 MCP 转换为 API 方式进行代码开发，后续将会支持本地脚本、数据库、存储等本地服务。也会默认集成 Supabase 、Appwrite 等相关三方服务。

模型路由

Hawa Code 收到用户指令会通过一个极小的模型进行业务识别，如果指令问题可以通过 code mode 执行代码解决，就不再执行推理，如果没有相关的代码才会路由到大的模型上进行推理。这些极小的模型也可能是直接部署在用户的电脑上而不是部署在云端。

UI 交互

当前 Agent 模型交互相应内容格式主要是 markdown 格式，对于一些复杂信息展示效果比较弱，比如查询一些商品信息，应该像浏览器一样给出一个优美的产品图片列表页面，当前 Hawa Code 支持在浏览器端使用，code mode 后续会支持返回 HTML 富文本格式，可以支持更好的交互体验。
